# 项目目录与逐文件代码说明

本文对应当前本地版本，按“目录 → 文件 → 主要代码块及作用”说明。它是源码导读，不是逐行翻译；第三方依赖和生成文件不逐行解释。

## 1. 项目现在是什么结构

这是 React + TypeScript + Vite 的纯前端工具。协议识别、报文解析、组帧、校验和计算、Excel 导出都在浏览器中执行。目前没有登录接口、服务器数据库或设备通信服务；生成指令不等于已经向设备下发。

```text
index.html
└─ src/main.tsx                     页面入口、加载全局样式
   └─ app/studio.tsx                工作台状态、操作及页面协调
      ├─ app/components/            可复用界面组件
      ├─ app/hooks/                 记录管理 React Hook
      └─ lib/
         ├─ protocols/registry.ts   自动识别和选择解析器
         ├─ protocols/*.ts          协议算法、组帧及展示数据模型
         ├─ records/               浏览器记录存储
         └─ export-xlsx.ts          Excel 文件生成
```

典型解析链路：输入 HEX → 校验输入格式 → 注册表匹配协议 → 对应解析器校验并解析 → 统一 `ParseResult` → 展示组件 → 保存本机记录。

典型组帧链路：填写参数 → 对应纯函数编码字段 → 计算长度和校验码 → 展示完整帧 → 复制或批量导出。此链路不连接设备。

## 5. `app/studio.tsx` 主页面内部代码

这是当前最大的页面协调文件，主要职责分为以下几块：

1. **状态定义**：当前模块、原始帧、解析结果、结果标签页、主题、复制反馈、Modbus 解码参数、组帧参数和批量表号等。
2. **页面切换**：协议解析、指令生成、协议中心、样例和解析记录的入口及内容组合。
3. **报文操作**：`parseFrame` 调用协议注册表；`useSample` 载入样例；`formatInput` 格式化；`pasteFrame`、`clearFrame`、`importText` 管理输入；`exportJson` 导出结果。
4. **复制交互**：`copyText` 负责剪贴板写入，`actionFeedback` 和定时恢复负责成功反馈。新复制入口应复用现有模式，不在每个按钮中增加不同规则。
5. **记录操作**：使用 `useParseRecords` 保存、查看、删除和重新解析；Modbus 记录包含当时的解释参数。
6. **结果展示辅助组件**：`FieldTable`、`FieldExplanation` 展示字段；`ByteMap` 根据偏移映射字节；`ElectricReadings` 展示费率；`ElectricReportDetails` 展示电量转换过程；`ModbusOverview` 展示通用寄存器解码。
7. **指令生成**：按当前选定功能调用各组帧纯函数，组织参数表单、字段组成表和批量导出；批量表号去重并限制数量。
8. **协议中心**：展示注册协议、支持能力和关联样例；展示名称不直接使用内部文件名。
9. **主题与图标**：主题状态同步到页面属性；`ToolIcon`、`BrandMark`、`NavIcon` 等渲染图标。

该文件负责“组织流程”，具体字节算法主要在 `lib/protocols`。后续可继续拆分页面模块，但不宜为了一个小功能再复制一套解析或反馈逻辑。

## 11. 本机记录与 Excel

### `lib/records/record-store.ts`

- 定义 `ParseRecord`、`RecordStorage`、存储键和最多 20 条限制。
- `createLocalRecordStore` 封装加载、保存和清空，兼容旧版数组及版本化格式。
- 验证读出的对象和 Modbus 配置，处理 JSON 损坏、未知版本及浏览器禁用存储；避免静默覆盖无法识别的旧数据。
- `createParseRecord` 把原始帧、结果摘要及必要解释参数转为可保存记录。
- 当前只是当前浏览器的 localStorage，不随账号同步，也不是服务器历史记录。

### `lib/export-xlsx.ts`

`createXlsxBlob` 生成真正的 XLSX；内部有 XML 转义、列名转换、工作表 XML、ZIP 文件头及 CRC32；`downloadXlsx` 触发下载。表号和 HEX 以字符串单元格保存，避免前导零丢失。这里 ZIP 使用的 CRC32 与 Modbus CRC16 不是同一算法。

## 14. 检查和上传注意事项

```bash
pnpm test          # 协议和存储回归
pnpm typecheck     # 严格类型和未使用代码检查
pnpm format:check  # 已配置源码范围的格式检查
pnpm build         # 生成 dist
pnpm check         # 依次执行以上检查
```

发布来源需要分清：Git 提交保存的是源码；Pages 发布的是 CI 构建出的 `dist`。当前自动发布只监听 `main`，功能分支上传成功不表示线上已经更新。依赖、临时输出、缓存和浏览器中的解析记录均不属于本次上传源码。
