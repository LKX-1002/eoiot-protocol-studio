# EOIOT Protocol Studio

源一物联仪表协议解析与调试工作台。采用 React、TypeScript 与 Vite，解析与组帧在浏览器本地完成，目前尚未接入登录或后端数据库。

目录、逐文件职责、主要代码块及调用关系见 [项目源码导读](docs/PROJECT_GUIDE.md)。

## 已实现

- CJ/T 188 小口径水表解析
- 武汉沃特曼 9021、9023、9025 解析器
- 自动识别协议；协议内核 API 支持指定解析器，界面使用自动识别
- 字段偏移、HEX 字节地图、诊断和 JSON 输出
- 沃特曼历史数据、流量、压力、温度、电压、设备信息和告警字段
- 白天 / 夜间主题切换
- 插件式协议注册表
- Joymeter MBus、4G 水表解析与写入指令生成
- Modbus RTU 03/04 读取组帧、自定义数值解析、CRC16 计算
- DL/T 645-2007 组合、正向、反向有功总量、费率 1–8 及实际返回费率数据块的请求/应答
- 645/188 CS 校验和计算、批量指令 Excel 导出
- 版本化本机解析记录，最多 20 条；兼容旧记录数组

自定义 645 DI 可生成和识别普通读取请求，但未列出的应答 DI 不会被猜测为电量。费率 1–4 的尖峰平谷标签沿用已确认设备的配置，其他设备须核对其费率定义。

## 质量检查

```bash
pnpm test          # Node 内置测试运行器：协议样例、错误帧、组帧、记录损坏及存储失败
pnpm typecheck     # 严格类型检查，检查未使用变量和参数
pnpm format        # 按统一格式整理源码（会修改格式）
pnpm format:check  # 只检查格式
pnpm check         # 测试、类型、格式与生产构建；CI 发布前也执行
```

测试使用 TypeScript 转译加载器在内存中运行协议模块，不生成临时源码文件；类型正确性由独立 `typecheck` 保证。测试不连接真实设备，不改动浏览器里的用户记录。

## 记录存储与恢复

- `lib/records/record-store.ts` 负责运行时字段校验和版本化读写；`app/hooks/use-parse-records.ts` 负责页面状态。
- 旧数组记录可读取，下一次保存时写为 `{ version: 1, records: [...] }`，不会在读取时改动原数据。
- 损坏项、未知版本或读取失败会显示提示，原存储不会自动覆盖。新记录仍可暂存在当前页面；确认清空后才重新启用持久保存。
- 写入空间不足不影响解析成功；页面会明确提示记录未持久保存。删除或清空存储失败也会提示，不能仅靠页面状态宣称操作已持久完成。
- 目前记录仅属于当前浏览器，不具备账号隔离能力；未来账号接口只替换记录存取层，不改变协议解析内核。

## 注释与维护约定

- 公共协议函数说明输入/输出、字节范围、端序、单位、异常条件；涉及兼容时写明原因。
- 区分设备协议已确认内容与可选/推测内容，不把单个型号的费率、单位当作通用规则。
- 修改能力或记录格式时同步更新测试、能力目录与 README，不保留过时的样例数量、布局名称或修复过程描述。
- 保持状态更新函数纯净，浏览器存储、网络请求等副作用不放进 React 状态更新回调。
- 指令目录的响应式规则集中在 `workbench-refinement.css`：1200px 以下为同目录抽屉，800px 以下参数/结果纵向排列。

## 部署到 GitHub Pages

仓库包含 `.github/workflows/pages.yml`。将代码推送到 `main` 后，在 GitHub 仓库的
`Settings → Pages → Build and deployment` 中选择 `GitHub Actions`，工作流会自动构建并发布 `dist`。

Vite 使用相对资源路径，因此部署到 `https://<用户名>.github.io/<仓库名>/` 时无需修改仓库名配置。

## 目录结构

```text
app/studio.tsx          工作台界面与交互
app/globals.css         设计系统与响应式样式
app/components/         可复用的目录、表单和结果组件
app/hooks/              记录状态与副作用管理
lib/protocols/          协议解析内核
lib/records/            记录结构校验、版本兼容和本机存储
tests/                  持久化的协议与存储回归测试
src/main.tsx            浏览器入口
```

新增协议只需实现 `ProtocolParser` 接口，并加入 `lib/protocols/registry.ts`。

## 界面扩展约定

- 新增功能沿用现有页面布局、主题变量、表格、折叠详情与工具栏交互；参考图用于借鉴，不直接还原另一套页面。
- 概览优先展示业务结果和关键换算；完整帧结构复用“字段解释”和“字节地图”，避免重复长卡片。
- 新复制入口使用现有工作台的 `copyText`、`actionFeedback` 和恢复计时，不另建复制规则。按钮仅复用展示组件，保持勾、“已复制”、禁用及失败反馈一致。
- 修改后运行 `pnpm check`，确认本地预览服务及页面资源可访问，再提供预览链接。
